# ADR-240: the mutation rows, and the test that kills each

This is the table [ADR-240](decisions.md#adr-240--idempotency-keys-the-record-is-written-with-the-write-and-travels-with-it-and-a-member-takes-keys-only-while-every-member-carries-records) refers to: every mutation row of the idempotency-keys work, run again together on the merged head. Each row is a change to the source that must make a test fail. Each piece ran its own harness against its own tree as it was built; here every row was run on `git archive` exports of the head of the work (`f86aa2e5`; the rows that ran again are described below), the integration of storage (S), the front (F), the executor (E), replication (R), the HTTP cluster tests (C), coverage with L1 and the G8 lookahead (G), the page records delta (P), the model (M) and the docs, and of the fixes that followed: the fixes after the review of the merged head (Y), records that outlive a drop and the contested flag (A), the fingerprint's golden vectors (X), the page byte budget and the guards of the records base (B), a replay's delta too large for its page (Z), the gate split (GS) and the review of the fixes (V). The totals below are counted from these tables by `scripts/idempotency-mutants/count.py`, which checks them, and the ADR-240 summary that quotes them, and rewrites them with `--write`.

**How a row was run.** A row is one or more exact replacements of the post-format source, applied in order, each of which must occur exactly once at its turn, or the row is not run. It was applied to an export, never to a worktree; its suites ran under bash at `nice -n 10`, each under a timeout that kills the suite's whole process group (a hang is a kill: an engine write inside `write_batch` can deadlock), stopping at the first suite that failed; then the files it touched were copied back from a second, pristine export and compared with it, and any proptest seed the mutant left was removed. A suite that failed before any test ran is not a kill. Before any row, every suite of every row, its wider suites included, ran on the unmutated export and passed, every test binary of it having run at least one test, and every test a row names as its killer (from its piece's own run, under its current name) ran there and passed. Eight exports ran side by side, each with its own target directory and its own baseline, with the tests' temporary stores (`TMPDIR`) on a RAM disk: the suites are fsync-bound, and none checks how long an fsync takes (the gates ran on the disk). The rows of the cluster tests on real kimmyd processes, whose waits are bounded in time, ran last, on a ninth export, once the rest had finished, with their stores on the disk. Each export was whole and equal to its pristine copy at the end. *Killed by* names the tests that failed on this run, by function name.

**The last rows.** The model changed after those exports were taken, in its test file and nothing else of the code, and the 103 model rows whose verdicts depend on that file ran again on `3f93baf2`, 78 in the same instances and 25 in a container on the host, whose result stands for each. The 13 rows of the cluster tests on real kimmyd processes ran in a container on a separate host, on `260e0445`, one row at a time with their stores on its disk. A container run bounds a suite by three times its unmutated time plus a margin and kills any test process that passes a memory guard (one above 4,096 MB resident, or all together above 5,600 MB, read every half second), recording the row as *killed (memory)*. Row M12zx of P ran on the host before that guard existed: its test process grew to 14.8 GB resident and was killed after 812 s, and it is recorded the same way, with that evidence. A hang is a kill and a memory kill is a kill; both are counted as killed below, with their number.

**Rows that had moved.** On the first combined run (`9922b699`), 35 of its 265 rows no longer applied: 32 were re-pointed with the same meaning and three superseded, their Notes saying so, and the coverage piece's eight re-runs of C's rows, the same edit and the same test, ran once, as C's. The change under which a record outlives a drop of its collection, with the contested flag, and the fixes that followed moved more. Nine are retired: what they planted is now the design (the life rule at the lookup and on store, the purge and the late drop's sweep of records), and the A section plants the inverse. One model row is retired as equivalent under that change, with the argument. The rest were re-pointed with the same meaning, each Note saying what moved, and one model row is re-worded for that change. Tests that were renamed since are named by their new names; two that it removed (`a_record_of_an_earlier_life_is_never_replayed`, `a_record_is_judged_by_its_last`) are named by no row.

**Survivors.** A row its own suites did not kill ran its wider suites, where it has them: for the rows the first combined run killed only so, the head's idempotency suites across the crates (kimmy-storage's `idempotency`, `page_delta`, `modify::`, `gc::`, `rewind` and `backup` tests, kimmy-cluster's `--test idempotency` and its `idempotency`, `replay_tests` and `transport::tests` lib tests, less `a_replay_of_many_pages_is_reported_once_not_once_per_page`, whose scoped log subscriber misses a line in shared-process runs of the unmutated tree, kimmy-api's lib tests, `--test idempotency` and `--test api`, and kimmy-mcp's `--test mcp`), or the test added for it with the first combined run, by its filter; for the model's rows the model alone does not see, the page records delta's or the fixes' suite for the same patch. A row still standing after that is recorded as equivalent, with the argument; none other stands. One row survived a dry run of this table on an earlier head of the work, P:M12r, and is killed by a test added for it (`idempotency_log_tests.rs`).
